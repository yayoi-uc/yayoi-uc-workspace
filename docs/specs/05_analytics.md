## 1. 概要

### 1.1 目的
売上・在庫・広告データを統合し、商品パフォーマンスを可視化。
データに基づいたリオーダー判定を自動化し、機会損失と過剰在庫を防ぐ。

### 1.2 解決する課題
| 現状の課題 | システムで解決 |
|-----------|--------------|
| 売上データがECプラットフォームに分散 | データ統合・一元表示 |
| 広告費と売上の紐付けが手動 | ROAS自動計算 |
| リオーダー判断が遅い/感覚的 | 自動判定アルゴリズム |
| 商品ごとの利益が正確にわからない | 原価・広告費込みの利益計算 |

### 1.3 ユーザーストーリー
- **経営者として**、全商品の売上・利益・広告効率を一覧で把握したい
- **マーケ担当として**、広告費に対するROAS（広告費用対効果）を確認したい
- **発注担当として**、リオーダーすべき商品を自動で提案してほしい
- **経営者として**、売上トレンドと在庫推移を時系列で分析したい

## 6. ビジネスロジック

### 6.1 主要KPI計算式

```
■ 粗利 = 売上 − 原価 − プラットフォーム手数料
■ 粗利率 = 粗利 ÷ 売上 × 100
■ ROAS = 売上 ÷ 広告費
■ CPA = 広告費 ÷ コンバージョン数
■ 在庫日数 = 現在庫数 ÷ 日次平均販売数
■ 在庫回転率 = 期間中の販売数 ÷ 平均在庫数
```

### 6.2 リオーダー自動判定アルゴリズム

```
【判定条件】
1. 在庫日数 < 閾値（デフォルト30日）
2. 直近4週の販売トレンドが「横ばい」または「上昇」

【優先度判定】
- 🔴 High:   在庫日数 < 14日 AND 売上トレンド上昇
- 🟡 Medium: 在庫日数 < 30日
- 🟢 Low:    在庫日数 < 45日 AND 季節商品

【推奨発注数の算出】
  推奨発注数 = 週次平均販売数 × 目標在庫週数（デフォルト8週）
             − 現在庫数
             + 安全在庫（週次平均販売数 × 2週）

  ※ メーカーの最小ロットに切り上げ
  ※ メーカーのリードタイムを加味
```

### 6.3 売上トレンド判定

```
直近4週の売上を線形回帰し、傾きで判定:
- 上昇:   傾き > +5%
- 横ばい: -5% ≦ 傾き ≦ +5%
- 下降:   傾き < -5%
```
